| Expression | Value | Type | Why |
| --- | --- | --- | --- |
| `7 / 2` | `3.5` | `float` | `/` is true division and always gives a float |
| `7 // 2` | `3` | `int` | `//` is floor division (Thursday's issue) |
| `"7" * 2` | `'77'` | `str` | a string times an int means "repeat" |
| `7 > 2` | `True` | `bool` | comparisons produce booleans |
| `2 ** 0.5` | `1.4142135623730951` | `float` | $\sqrt 2$, approximately |
| `int("7") + 1` | `8` | `int` | `int(...)` converts text to a number |

**2.** It prints `6 5`.

- After `x = 5`: label `x` → `5`.
- After `y = x`: `y` is tied to the same `5`.
- After `x = x + 1`: Python computes `5 + 1 = 6`, a **new** value, and re-ties `x` to it. `y` is still tied to `5`.

Integers can't be changed in place, so `x + 1` can't "modify the 5". It creates a 6.

**3.** It prints `['red', 'green'] ['blue', 'yellow']`.

- `p = ["red"]`: `p` → list A `["red"]`.
- `q = p`: `q` → the same list A.
- `q.append("green")`: changes list A to `["red", "green"]`. Both `p` and `q` see it.
- `q = ["blue"]`: re-ties `q` to a **new** list B. `p` still points at A.
- `q.append("yellow")`: changes B only.

The third line is aliasing: changing the object through one label is visible through the other. The fourth line breaks the alias.

**4.** Compare with a tolerance instead of exactly:

```python
import math

print(0.1 + 0.2 == 0.3)              # False
print(math.isclose(0.1 + 0.2, 0.3))  # True
print(abs((0.1 + 0.2) - 0.3) < 1e-9) # True: the do-it-yourself version
```

`math.isclose` uses a *relative* tolerance by default (`rel_tol=1e-09`), which scales with the size of the numbers. That matters: a difference of $10^{-9}$ is huge for numbers around $10^{-12}$ and negligible for numbers around $10^{12}$. Never test floats with `==` unless you know the values are exact (like small integers stored as floats).

**5.**

```python
name = "Ada"
age = 36
height = 1.65

print(name + " is " + str(age) + " years old and " + str(height) + " m tall.")
# or, more readably, with an f-string:
print(f"{name} is {age} years old and {height} m tall.")
```

Both print `Ada is 36 years old and 1.65 m tall.` `"is " + 36` would raise a `TypeError` (strings and ints don't mix), which is why the first version needs `str(...)`.

**6. ★**

```python
a = [1, 2]
b = a
c = [1, 2]
print(a == c)  # True:  same contents
print(a is c)  # False: two different list objects
print(a is b)  # True:  two labels, one object
```

**`==` asks "do these values look the same?"** It compares contents. **`is` asks "are these the same object?"** It compares the arrows: do both labels point at the same thing? `a` and `c` are two separate lists that happen to have equal contents. `a` and `b` are one list with two names.

With `x = 1000; y = 1000; print(x is y)`, the answer **depends on how you run it**. In a script it usually prints `True`, because Python compiles the whole file at once and reuses one constant object for the two identical literals. Typed line by line in the REPL it usually prints `False`, because each line is compiled separately and creates its own `1000`. (Small integers from −5 to 256 are always shared, so `x = 7; y = 7; x is y` is always `True`.)

Whether two equal numbers are the same object is an **implementation detail** that can change between runs and versions. You care whether the *values* are equal, so use `==`. Use `is` only to ask about identity, almost always in the form `x is None`.
