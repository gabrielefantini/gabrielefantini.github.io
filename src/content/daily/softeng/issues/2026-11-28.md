## The week in one page

**Monday: what a program is.** A program is a recipe for a perfectly literal cook: unambiguous, executable, finite. The CPU runs one loop forever: **fetch** the instruction at the program counter, **decode** it, **execute** it. We built that loop in Python, and adding a conditional jump (`JNZ`) let a 5-instruction program run as long as it needs. The deep idea: **programs are data**, stored in memory like everything else.

**Tuesday: compilers and interpreters.** A compiler translates everything ahead of time (fast to run, errors caught early). An interpreter carries the program out step by step (instant start, interactive). Most real systems are hybrids: Python and Java compile to **bytecode** for a **virtual machine**, and JITs compile hot code on the fly. Compiled vs interpreted is a property of an implementation, not a language.

**Wednesday: values, types, names.** Values have types (`int`, `float`, `str`, `bool`). Names don't. **A variable is a label tied to a value, not a box.** `b = a` ties a second label to the same object (aliasing). `=` moves labels, while methods like `append` change objects.

**Thursday: expressions are trees.** Precedence, associativity and parentheses decide the tree, and evaluation goes bottom-up. Visiting the tree in post-order gives Reverse Polish Notation, which a stack machine executes. `//` rounds down and `%` takes the sign of the divisor. `and`/`or` short-circuit.

**Friday: talking to the world.** The REPL is a four-line loop. Input is always text: convert and check it at the boundary. f-strings format output. Every program gets **stdin, stdout and stderr**, and the shell can redirect and pipe them.

> **The thread running through it all.** The same machine kept reappearing at different levels: a loop that reads an instruction and carries it out. It's the CPU (Monday), Python's bytecode VM (Tuesday), your RPN interpreter (Tuesday and Thursday) and the REPL (Friday). Computing is layers of interpreters, all the way down to the silicon.

Next week: **control flow**. `if`, `while`, `for`, boolean logic in code, and how to debug when it all goes wrong.

## Mixed problems

**1.** Monday's toy machine has no `IF` instruction, only `JNZ`. Show how to get the effect of "if `acc` is not zero, print it; then halt" using `JNZ`, `PRINT` and `HALT`. (Hint: you may need a jump that skips over the `HALT`.)

**2.** Explain in your own words why a typo in a variable name inside a rarely-used branch of a Python program can go unnoticed for months, while the same typo in Java is caught immediately. Name one tool or practice that reduces this risk in Python.

**3.** What's printed? Draw the labels and arrows.

```python
a = [1, 2]
b = [a, a]
a.append(3)
b[0] = [0]
print(a, b)
```

**4.** Without running it, give the value and type of each: (a) `7 // 2 * 2 + 7 % 2`; (b) `-7 // 2 * 2 + -7 % 2`; (c) `not 3 > 2 or 1 / 0`; (d) `2 ** -1`. Which identity from Thursday explains (a) and (b)?

**5.** Convert to RPN, then evaluate: (a) `(8 - 3) * (2 + 4)`; (b) `8 - 3 * 2 + 4`; (c) `100 / (2 * 5) / 2`.

**6.** Write a program that reads lines from stdin and prints, to stdout, only those that look like integers (e.g. `42`, `-7`), and writes `skipping: <line>` to stderr for the others. Show a command that saves the valid numbers to `good.txt` while the skipped lines appear on screen.

**7. ★** *Synthesis: a two-stage pipeline.* Write `compile.py`, which reads one infix expression per line with **only `+` and `*`, single-digit numbers and no spaces or parentheses** (e.g. `2+3*4`) and prints its RPN (`2 3 4 * +`). Then write `run.py`, which reads RPN lines from stdin and prints their values. Check that `printf "2+3*4\n1*2+3*4\n" | python3 compile.py | python3 run.py` prints `14` and `14`. (Hint for the compiler: split the line on `+` first, then split each part on `*`. Why does splitting on `+` *first* give the right precedence?)
