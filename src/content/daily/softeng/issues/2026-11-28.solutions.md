**1.** Jump *over* the early `HALT` when `acc` is non-zero:

```python
program = [
    ("LOAD", 5),      # 0  (try 0 here too)
    ("JNZ", 3),       # 1  acc != 0 -> go to the PRINT
    ("HALT", None),   # 2  acc == 0 -> stop without printing
    ("PRINT", None),  # 3
    ("HALT", None),   # 4
]
```

With `LOAD 5` it prints 5. With `LOAD 0` it prints nothing. An `if` statement is just a conditional jump around a block of code, and compilers generate exactly this shape (you saw `POP_JUMP_IF_FALSE` on Tuesday).

**2.** CPython compiles the file to bytecode before running it, but it only checks *grammar* at that point. Looking up a name happens at **run time**, when that exact line executes. A misspelled name in a branch that rarely runs (an error handler, say) is never looked up, so the mistake sleeps until the day that branch runs, often in production. Java's compiler resolves every name and type in the whole program before producing any bytecode, so the typo stops the build. Ways to reduce the risk in Python: **linters** such as `ruff` or `pyflakes`, which flag undefined names; **type checkers** such as `mypy`; and **tests that exercise every branch** (coverage, week 64).

**3.** It prints `[1, 2, 3] [[0], [1, 2, 3]]`.

- `b = [a, a]`: `b` is a new list whose two slots both point at the same list `a`.
- `a.append(3)`: changes that shared list, so both slots of `b` now see `[1, 2, 3]`.
- `b[0] = [0]`: re-ties slot 0 of `b` to a new list. That moves one arrow inside `b` and doesn't touch `a`.

Slot 1 still points at `a`. List slots are labels too.

**4.** (a) `(7 // 2) * 2 + (7 % 2)` = 6 + 1 = **7** (`int`). (b) `(-7 // 2) * 2 + (-7 % 2)` = (−4)·2 + 1 = **−7** (`int`). Unary minus binds tighter than `//` and `%`. (c) `not 3 > 2` is `not True`, which is `False`, so `or` must evaluate `1 / 0`: **`ZeroDivisionError`**. Short-circuiting only helps when the left side already decides the answer. (d) **`0.5`** (`float`): a negative power is a reciprocal.

(a) and (b) are both the identity $a = b \cdot (a // b) + (a \% b)$ with $b = 2$, so each expression gives back $a$.

**5.** (a) `8 3 - 2 4 + *` → 5 · 6 = **30**. (b) `8 3 2 * - 4 +` → (8 − 6) + 4 = **6**. Left-associativity puts the `-` before the `+`. (c) `100 2 5 * / 2 /` → (100 / 10) / 2 = **5.0**.

**7. ★**

`compile.py`:

```python
import sys

for line in sys.stdin:
    line = line.strip()
    if not line:
        continue
    terms = line.split("+")              # lowest precedence first: the root's children
    out = []
    for i, term in enumerate(terms):
        factors = term.split("*")
        out.append(factors[0])
        for f in factors[1:]:            # a*b*c  ->  a b * c *
            out.append(f)
            out.append("*")
        if i > 0:                        # t1+t2+t3  ->  t1 t2 + t3 +
            out.append("+")
    print(" ".join(out))
```

`run.py`:

```python
import sys

for line in sys.stdin:
    stack = []
    for token in line.split():
        if token in ("+", "*"):
            b = stack.pop()
            a = stack.pop()
            stack.append(a + b if token == "+" else a * b)
        else:
            stack.append(int(token))
    print(stack[0])
```

The pipeline prints `14` and `14`. For instance `1*2+3*4` compiles to `1 2 * 3 4 * +`.

**Why split on `+` first?** The operator with the **lowest** precedence ends up at the **top** of the tree: in `1*2+3*4`, the root is `+` and its children are the products `1*2` and `3*4`. Splitting on `+` first finds the root's children. Then splitting each child on `*` builds the subtrees below. We emit each subtree's RPN before the operator that combines them: post-order, exactly as on Thursday. Real parsers generalise this idea, one level per precedence level, with *recursive descent* (week 54).

You now have a **compiler** and a **virtual machine** connected by a **pipe**, with a well-defined intermediate language (RPN) between them. That's the architecture of Java and Python in miniature, built in week 1.
