## The REPL is just a loop

All week we've been typing at Python's `>>>` prompt. It's called the **REPL**, and the name is the whole algorithm:

1. **Read** a line of text from the user.
2. **Eval**uate it.
3. **Print** the result.
4. **Loop** back to step 1.

That's Monday's fetch–decode–execute cycle again, one level up. Here's a working REPL for arithmetic. `eval` is a built-in that evaluates a string as a Python expression:

```python
while True:
    line = input(">>> ")          # READ
    if line == "quit":
        break
    result = eval(line)           # EVAL
    print(result)                 # PRINT
                                  # LOOP (back to while)
```

Run it, type `2 + 3 * 4`, and you get `14`. You've built the tool you've been using all week. Real REPLs add error handling (try typing `1/0` into yours), history and multi-line input. But the heart is these four lines.

> **A warning you'll hear again.** `eval` runs *any* Python code, including code that deletes files. Never call it on text that comes from someone you don't trust. Injecting code into an `eval`-like function is one of the oldest attacks there is (week 86). Our toy REPL is fine because you're the only user.

## Input: everything arrives as text

`input(prompt)` shows the prompt, waits for the user to type a line and press Enter, and returns that line **as a string**, always:

```python
age = input("How old are you? ")
print(age + 1)    # TypeError: can only concatenate str (not "int") to str
```

The user typed `36`, but `age` is the *string* `"36"`. You must **convert** it:

```python
age = int(input("How old are you? "))
print(age + 1)    # 37
```

If the user types `thirty-six`, `int()` raises a `ValueError`. Handling that politely is week 8's topic. For now, notice the principle: **data from outside your program is text, untrusted, and possibly wrong.** Convert it and check it at the boundary, before it gets deeper into your code.

## Output: print and f-strings

`print` takes any number of values, converts each to text, and writes them separated by spaces, followed by a newline:

```python
print("total:", 60, "EUR")         # total: 60 EUR
print("a", "b", "c", sep="-")      # a-b-c
print("no newline", end="")        # the next print continues this line
```

To build text with values inside, use an **f-string**: put `f` before the quotes and write expressions in `{braces}`:

```python
name = "Ada"
price = 19.9
qty = 3
print(f"{name} pays {price * qty} EUR")      # Ada pays 59.699999999999996 EUR
print(f"{name} pays {price * qty:.2f} EUR")  # Ada pays 59.70 EUR
```

After a colon you can add a **format spec**: `:.2f` means "fixed-point, 2 decimals". (Notice the float approximation from Wednesday sneaking in!) Other useful specs: `{n:5d}` pads an integer to 5 characters, `{x:>10}` right-aligns text in 10 characters, and `{n:,}` adds thousands separators. A neat debugging trick: `f"{price=}"` prints `price=19.9`, the expression *and* its value.

- **Standard input** (`stdin`): where `input()` reads from.
- **Standard output** (`stdout`): where `print()` writes to.
- **Standard error** (`stderr`): where error messages go. Write to it with `print("oops", file=sys.stderr)` after `import sys`.

By default all three are connected to your terminal, which is why they look like one thing. But the **shell can reconnect them**, without your program knowing or caring:

```bash
python3 app.py < numbers.txt      # stdin comes from a file
python3 app.py > results.txt      # stdout goes to a file (errors still on screen)
python3 app.py 2> errors.log      # stderr goes to a file
python3 gen.py | python3 app.py   # gen's stdout becomes app's stdin: a pipe
```

That's why stdout and stderr are separate: you can save the results to a file and still see the errors on screen. And the **pipe** `|` is one of the most powerful ideas in computing. Small programs that each read text and write text can be snapped together like Lego. This is the Unix philosophy, and you'll use it daily (weeks 9 and 39).

> **The big picture.** A program is a function from input to output. The three streams are its standard plugs, and redirection lets you rewire them from the outside. Write programs that read stdin and write stdout, and they'll combine with everything else.

> **Why it matters.** Every tool you'll ever build, from a script to a web server, is "read input, compute, write output" at heart. Getting the boundary right (convert, validate, report errors on the right channel) is what separates a script that works on your machine from software that works for other people.
