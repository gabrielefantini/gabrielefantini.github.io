## Values have types

Open a terminal, type `python3`, and you're in the Python **REPL**, a prompt (`>>>`) where you type something and Python immediately shows the result. (Friday's issue explains how it works.) Try this:

```python
>>> 42
42
>>> 3.14
3.14
>>> "hello"
'hello'
>>> True
True
```

Each of these is a **value**, a piece of data. Every value has a **type**, which says what kind of thing it is and therefore *what you can do with it*. Python will tell you:

```python
>>> type(42)
<class 'int'>
>>> type(3.14)
<class 'float'>
>>> type("hello")
<class 'str'>
>>> type(True)
<class 'bool'>
```

The four basic types you'll use every day:

| Type | What it is | Examples |
| --- | --- | --- |
| `int` | whole numbers, of **any size** | `0`, `-7`, `2**100` |
| `float` | decimal numbers, approximately | `3.14`, `1e-9`, `0.1` |
| `str` | text ("string" of characters) | `"hello"`, `'Ciao!'`, `""` |
| `bool` | truth values | `True`, `False` |

Types matter because the same operator does different things to different types:

```python
>>> 2 + 3
5
>>> "2" + "3"
'23'
>>> "2" + 3
TypeError: can only concatenate str (not "int") to str
```

`+` adds numbers but *concatenates* (joins) strings. Mixing them is an error, because Python refuses to guess whether you meant `5` or `"23"`. That refusal is a feature. Languages that guess (JavaScript says `"2" + 3` is `"23"`) are famous for producing surprising bugs.

Two surprises worth knowing on day one:

- **`int` has no limit.** `2**100` gives all 31 digits exactly. Python grows the number as needed. (In C, integers have a fixed size and silently wrap around; week 11.)
- **`float` is approximate.** `0.1 + 0.2` gives `0.30000000000000004`. Computers store floats in binary, and $0.1$ has no exact binary representation, just as $\tfrac13$ has no exact decimal one. Never compare floats with `==`. (Week 11 explains the details.)

## Variables: the picture that matters

A **variable** is a name for a value. You create one with **assignment**, written `=`:

```python
price = 20
```

Read `=` as **"is now a name for"**, *not* "equals". `price = price + 1` is nonsense in maths, but perfectly sensible in Python: "compute `price + 1`, then make `price` a name for the result."

Now the important part. There are two ways to picture a variable, and only one of them is right for Python.

**The wrong picture: a box.** `price` is a box with `20` inside. Assigning puts a new value in the box.

**The right picture: a label on a string.** Values live on their own, out in memory. A variable is a **label tied to a value**. Assignment ties the label to a (possibly different) value.

Why does the picture matter? Because of this:

```python
a = [1, 2, 3]   # a list: an ordered collection (week 4)
b = a
b.append(4)     # change the list that b is tied to
print(a)        # [1, 2, 3, 4]  !!
```

With the box picture, this makes no sense: we changed `b`, so how did `a` change? With the label picture, it's obvious. `b = a` **didn't copy the list**. It tied a second label to the *same* list. `b.append(4)` changes that one list, and `a` is tied to it too. Two names for one object is called **aliasing**, and it's behind a huge number of real bugs.

Compare with re-assignment:

```python
a = [1, 2, 3]
b = a
b = [9]         # re-tie b to a NEW list
print(a)        # [1, 2, 3]  — untouched
```

Assignment never changes an object. It only moves a label. **Changing an object** (like `append`) and **moving a label** (like `=`) are completely different operations. Once you see that, half of Python's surprises disappear.

> **The big picture.** Variables don't contain values. They *refer* to them. Python always passes these references around, never copies, unless you ask for a copy (`b = a.copy()`). Numbers and strings can't be changed in place (they're *immutable*, week 4), so for them the difference never shows. With lists and dictionaries, it shows constantly.

## Dynamic typing

In Python, **names don't have types; values do**:

```python
x = 42        # x is tied to an int
x = "hello"   # now tied to a str: perfectly legal
```

This is called **dynamic typing**. In Java or C (static typing), you declare `int x` and `x` can only ever refer to integers. The compiler checks this before the program runs. Each approach has a cost. Dynamic typing is flexible and quick to write; static typing catches whole classes of bugs early (remember yesterday's compile-time errors) and documents your intent. Modern Python lets you add optional **type hints**, `x: int = 42`, which tools can check without changing how the program runs. We'll compare the two philosophies properly in week 10.

> **Why it matters.** Almost every bug report that says "but I never changed that variable!" is an aliasing bug. Draw the labels and arrows, and you'll find it.
